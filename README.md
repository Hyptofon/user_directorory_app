# 📂 User Directory App (LR04)

Цей проєкт є виконанням лабораторної роботи **LR04: Навігація між екранами**. Додаток реалізує повноцінний каталог користувачів із тристепеневою навігацією, передачею даних між екранами та глобальним управлінням станом через `Provider`.

---

## 🎯 Виконані завдання 

Всі обов'язкові вимоги завдання успішно реалізовані:

1. **Модель User та структура проєкту:**
   - Клас `User` із п'ятьма полями (`id`, `name`, `job`, `email`, `phone`), всі `final`.
   - Реалізовано метод `copyWith()` для незмінного оновлення об'єктів.
   - Застосовано **Fail Fast Pattern**: валідація даних відбувається безпосередньо в ініціалізаційному списку конструктора — неможливо створити об'єкт із порожніми полями.
   - Структура проєкту розбита на тематичні шари: `screens/`, `models/`, `widgets/`, `providers/`, `routes/`, `constants/`, `theme/`, `utils/`.

2. **Home Screen:**
   - Список користувачів побудований на `ListView.builder` — жодного зайвого елемента у пам'яті.
   - Кожна картка виділена в окремий реюзабельний віджет `UserCardWidget`.
   - Список реактивно оновлюється через `Consumer<UserProvider>` — зміни профілю миттєво відображаються у списку.

3. **Profile Screen:**
   - `StatefulWidget` зберігає поточний стан профілю (`_currentUser`).
   - Повні дані користувача відображаються через компонент `InfoRowWidget`.
   - Реалізовано безпечну асинхронну навігацію з обов'язковою перевіркою `if (!mounted) return` після `await`.
   - При успішному збереженні з'являється `SnackBar` із підтвердженням.

4. **Edit Screen:**
   - Використовується `Form` із `GlobalKey<FormState>` та `AutovalidateMode.onUserInteraction` для UX-friendly валідації.
   - `TextEditingController` для кожного поля (`name`, `job`, `email`) ініціалізуються в `initState()` та коректно знищуються в `dispose()`.
   - Кнопка "Save" передає оновленого користувача назад через `Navigator.pop(SavedUser(updatedUser))`.
   - Кнопка "Cancel" повертає `Cancelled()` без жодних змін.

## 🌟 Реалізовані бонусні завдання 

Окрім базового функціоналу, реалізовано **всі три** опціональні бонусні завдання:

- [x] **Варіант A: Named Routes.** Навігацію централізовано у класі `AppRouter` через `onGenerateRoute`. Усі шляхи зберігаються у `AppRoutes` як константи — жодних magic strings.
- [x] **Варіант B: Custom Transition.** Перехід із головного екрану на профіль виконується через `PageRouteBuilder` із плавним `FadeTransition`.
- [x] **Варіант C: Hero Animation.** Аватарка користувача плавно "перелітає" між `HomeScreen` та `ProfileScreen` завдяки `Hero` із унікальним тегом `'avatar-${user.id}'`.

## 🏗️ Додаткові архітектурні рішення

Реалізовано ряд покращень, що виходять за межі вимог завдання:

- **State Management (Provider):** Список користувачів зберігається в `UserProvider`. Після редагування профілю виклик `context.read<UserProvider>().updateUser()` оновлює дані глобально — обидва екрани (список і деталі) одразу відображають актуальне ім'я.
- **Sealed class `EditResult`:** Замість повернення `User?` (з можливим `null`), `EditScreen` повертає типобезпечний результат: `SavedUser(user)` або `Cancelled()`. Це унеможливлює неоднозначність трактування `null`.
- **Design Tokens:** Всі рядки (`AppStrings`), розміри (`AppSizes`) та маршрути (`AppRoutes`) централізовані в папці `constants/`. Зміна будь-якого значення потребує правки лише в одному місці.
- **Reusable Widgets:** `CustomAppBar`, `UserAvatar`, `EditFormFields` — кожен з них відповідає лише за одну задачу і може бути повторно використаний у будь-якому місці проєкту.
- **Валідатори:** Клас `Validators` містить методи `required()` та `email()` (з перевіркою за RegExp), що використовуються у формі редагування.
- **Unit Tests:** Написано тест, що перевіряє коректність методу `copyWith` — оновлення одного поля не впливає на решту.

## 🚀 Як запустити

1. Переконайтеся, що встановлений [Flutter](https://flutter.dev/docs/get-started/install) версії 3.24.0+.
2. Відкрийте папку проєкту в терміналі.
3. Оновіть залежності:
   ```bash
   flutter pub get
   ```
4. Запустіть додаток:
   ```bash
   flutter run
   ```
5. Запустіть тести:
   ```bash
   flutter test
   ```
